# Architecture

Two parts, both small:

1. **The game:** a static site (HTML, CSS, vanilla JS ES modules) on GitHub Pages. No build step, no npm dependencies at runtime.
2. **The worker:** one Cloudflare Worker (`worker/`) that turns ideas into GitHub issues and stores the leaderboard in Workers KV.

```
Phone browser ──static files──▶ GitHub Pages (repo SvenGoerdes/roll-down-volkspark)
      │
      └──fetch JSON──▶ Cloudflare Worker "roll-down-ideas"
                          ├─ POST /ideas (and /) ─▶ GitHub REST API: create issue, label "idee"
                          ├─ POST /scores ────────▶ KV "LEADERBOARD", key "top"
                          └─ GET  /leaderboard ───▶ KV "LEADERBOARD", key "top"
```

## The game (`index.html`, `style.css`, `js/`)

**Rendering model.** Canvas 2D with fake 3D. World units: the path is `CORRIDOR` (8) wide, `x = 0` is the middle, `z` is the distance from the camera. Walls spawn at `z = 90` and move toward the player at `z = 4`. `view.js` turns `(x, z, height)` into screen coordinates on a descending logarithmic hill, anchored at the player. It precomputes inverse ground rows once per resize so the ground texture, wall feet, foliage and ice share that profile. The top part of the screen is a painted seasonal horizon (`assets/environment/*-horizon.webp`), cropped above the static walls in the reference; the ground is drawn row by row below the horizon.

**Main loop** (`main.js`): `requestAnimationFrame` → `update(dt)` (speed, spawning, collisions, power-ups, seasons, surfaces, effects) → `render()` (background, ground, a depth-sorted list of walls/plants/pickups/player, particles, overlays). `dt` is capped at 1/30 s. State machine: `loading → start → intro → playing → over → playing …` (over can go back to start to change the figure).

**Paint once, blit often.** Everything expensive (fog-blended seasonal horizons, ground tiles, tree/shrub clusters, gabion faces, pickup bubbles, light overlays) is painted once into offscreen canvases. The loop only copies them. This keeps phones at 60 fps.

**Game rules in short.** Difficulty follows the walls passed, not the time (ADR 0024): speed eases from 16 toward 28 units/s, the time between walls from 1.2 toward 0.65 s, the gap from 3.2 toward 1.95; the first five walls of each season are a breather, and after the first year (80 walls) gaps and intervals keep tightening slowly. Autumn gusts are announced 0.7 s ahead. Seasons change every 20 walls (spring: puddles, summer: faster and two gaps, autumn: wind gusts, winter: ice). Path surfaces change every 120–220 units (dirt normal, gravel bumpy, grass slower). Power-ups: helmet (extra life, stacks to 3), slow-mo (5 s), wider gaps (7 s).

**Ground material build (#75, ADR 0043), Berlin-Tour only.** Volkspark keeps the old ground; the Berlin-Tour tile set (`groundTiles['berlin-tour']`) loads and builds on first choice of that theme. `tools/build-ground-materials.py` extracts small ground-only crops from the approved local `ground-v2.png` study and makes them periodic in the travel direction. `ground-earth.webp` and `ground-verge.webp` feed the existing 384×512 tiles (8 world units, 5 mip sizes). Soft verge masks and seasonal decoration are baked once; terrain inversion and object anchoring are unchanged. Split-row blits overlap slightly so Canvas subpixel coverage cannot expose the background along a tile seam; no extra blits or render layers. The full study/phone presentation is never loaded at runtime.

**Testing hook.** `index.html#debug` exposes `window.rollDown` (`game()`, `start`, `intro`, `step`, `setSeason`, `spawn`, `update`); `step(dt)` advances one frame by hand (the wind strength follows `game().passed`, so set it too when you jump to autumn with `setSeason(2)`), for panes where `requestAnimationFrame` is paused during scripted browser tests. `?preview=autumn#debug` provides a frozen seasonal view; add `&surface=gravel` or `&surface=grass` to check surfaces. `&width=390&height=844` fixes the debug game frame for repeatable captures; `&near=4.8` shows a close approaching basket. Basket height is 1.65, with texture cropping to preserve wire proportions.

**Security on the page.** A CSP meta tag allows only own files and the worker URL. User text (names, ideas, leaderboard entries) is only ever set with `textContent`.

## Sightseeing (#28, ADR 0034/0035)

`theme-select.js` bietet auf dem Startscreen „Volkspark“ (Vorgabe) / „Berlin-Tour“. `main.js` übernimmt die Sitzungswahl in jeden neuen Spielzustand; schnelle Wiederholungen behalten das Thema. Nur die Berlin-Tour lädt vor dem Start die drei optionalen Tor-WebPs über `gate-sprites.js`. Fehlschläge lassen den Start wiederholbar; Volkspark braucht diese Bilder nicht.

`render-scene.js` ersetzt dort ausschließlich den vorhandenen Wand-Zeichenaufruf durch `render-gate.js`: Dach/Quadriga bleiben mittig, volle Säulen stehen innerhalb der festen Spannen an den aktuellen Lückenkanten, Holzsperren schließen alle übrigen Spannen. Der kleine Zeichenpfad nimmt die konkreten Bildteile samt Weltmaß-Ankern entgegen; #71–#74 können ihre eigenen Teile verwenden, ohne neue Spiellogik oder ein Bauwerk-Framework. Gegenwärtig ist nur das Brandenburger Tor integriert. Fünf Tor-Motive sind registriert. Der Fernsehturm ist nach jüngster Nutzerentscheidung in keinem Thema Bestandteil des Spiels, auch nicht am Rand; #47 ist geschlossen, es gibt keine Turm-Schnittstelle.

`gateLayout()` bewahrt ursprüngliche `passages` und eine davon getrennte sichtbare `openings`-Vereinigung. `passesGate()` prüft nur die ursprünglichen Einzelspannen; die Laufzeit bleibt unverändert bei `passesWall()`. Layouts werden pro Hindernis und Lückenwerten zwischengespeichert und bei Aktivierung/Ablauf des Verbreiterungs-Pickups erneuert. Das Tor wird immer vollständig und deckend gezeichnet, ohne Sichtfenster (ADR 0052). Keine zusätzliche Gebäudetiefen-Kollision, keine Änderung von Spawn, Tempo, Abständen, Radius, Wertung oder Helmen.

Die Originalquelle ist das freigegebene detaillierte Blender-Modell, nicht der alte Generator aus ADR 0033. `render-brandenburg-sprites.py` und `build-gate-sprites.py` exportieren drei WebPs plus `gate-sprite-data.js` und `assets/landmarks/provenance.json`. 80.388 Bytes komprimiert, ca. 5,42 MiB RGBA; keine Laufzeit-3D-Engine. Die alten `sightseeing-*.py` bleiben als historische Offline-Vorbereitung erhalten, ohne durchfahrbaren Turmfuß. Grafikfreigabe des echten Spiels bleibt vor dem PR erforderlich.

**Berlin-Tour, mehrere Bauwerke (#71, ADR 0049).** `TOUR_LANDMARKS` (config) legt die Reihenfolge fest, `landmarkAt()` wählt je `WALLS_PER_SEASON` Mauern ein Bauwerk. `render-gallery.js` zeichnet die East Side Gallery: `galleryTiles()` füllt jede feste Spanne von der offenen Kante nach außen mit sechs Bucht-Sprites, beschnitten auf die Spanne. Kein Sichtfenster. Bilder und Herkunft: `assets/landmarks/gallery-provenance.json`.

## The worker (`worker/`)

| File | Job |
|---|---|
| `src/index.js` | Routing, CORS, origin allowlist, size/type checks, rate limits, daily idea cap |
| `src/idea.js` | Validate an idea, build the GitHub issue (text in a code block, names stripped of markdown) |
| `src/score.js` | Validate a score, merge it into the top 20, per-IP limiter |
| `wrangler.toml` | Worker name, repo var, KV binding |

Limits: ideas 5 per hour per IP and 100 per day in total; scores 20 per hour per IP; bodies up to 4 KB; JSON only. Only `https://svengoerdes.github.io` may call it (extra dev origins via the `DEV_ORIGINS` env var, unset in production).

The GitHub token is a Cloudflare secret, never in the repo or the browser. Details in [operations.md](operations.md).
**Oberbaumbrücke (#72, ADR 0053–0055).** `render-oberbaum.js` kachelt den Pfeiler über feste Spannen, setzt die Türme bei `OBERBAUM_TOWER_X` außerhalb des Wegs und den Bogen über Mauerhöhe. `PLANT_BEHIND_LANDMARKS` gibt Galerie und Brücke die Pflanzenreihenfolge. Herkunft: `assets/landmarks/oberbaum-provenance.json`.

**Reichstag (#73, ADR 0056–0058).** `render-reichstag.js` zeichnet die Flügel auf feste Spannen, füllt den Portikusbereich (`REICHSTAG_PORTICO`) mit Säulen im Abstand `REICHSTAG_COLUMN_STEP` und hängt Giebel mit Kuppel über Mauerhöhe. `TOUR_LANDMARKS` hat vier Einträge, der Reichstag steht im Winter. Herkunft: `assets/landmarks/reichstag-provenance.json`.
