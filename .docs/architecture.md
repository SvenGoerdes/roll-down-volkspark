# Architecture

Two parts, both small:

1. **The game:** a static site (HTML, CSS, vanilla JS ES modules) on GitHub Pages. No build step, no npm dependencies at runtime.
2. **The worker:** one Cloudflare Worker (`worker/`) that turns ideas into GitHub issues and stores the leaderboard in Workers KV.

```
Phone browser ──static files──▶ GitHub Pages (repo SvenGoerdes/roll-down-volkspark)
      │
      └──fetch JSON──▶ Cloudflare Worker "roll-down-ideas"
                          ├─ POST /ideas (and /) ─▶ GitHub REST API: create issue, label "idee"
                          ├─ POST /scores ────────▶ KV "LEADERBOARD", key "top"
                          └─ GET  /leaderboard ───▶ KV "LEADERBOARD", key "top"
```

## The game (`index.html`, `style.css`, `js/`)

**Rendering model.** Canvas 2D with fake 3D. World units: the path is `CORRIDOR` (8) wide, `x = 0` is the middle, `z` is the distance from the camera. Walls spawn at `z = 90` and move toward the player at `z = 4`. `view.js` turns `(x, z, height)` into screen coordinates on a descending logarithmic hill, anchored at the player. It precomputes inverse ground rows once per resize so the ground texture, wall feet, foliage and ice share that profile. The top part of the screen is a painted seasonal horizon (`assets/environment/*-horizon.webp`), cropped above the static walls in the reference; the ground is drawn row by row below the horizon.

**Main loop** (`main.js`): `requestAnimationFrame` → `update(dt)` (speed, spawning, collisions, power-ups, seasons, surfaces, effects) → `render()` (background, ground, a depth-sorted list of walls/plants/pickups/player, particles, overlays). `dt` is capped at 1/30 s. State machine: `loading → start → intro → playing → over → playing …` (over can go back to start to change the figure).

**Paint once, blit often.** Everything expensive (fog-blended seasonal horizons, ground tiles, tree/shrub clusters, gabion faces, pickup bubbles, light overlays) is painted once into offscreen canvases. The loop only copies them. This keeps phones at 60 fps.

| Module | Job |
|---|---|
| `config.js` | All tuning constants: sizes, seasons, surfaces, power-ups, worker URL |
| `logic.js` | Pure game rules (difficulty curve, gaps, seasons, surfaces, slip, helmets). Fully unit tested |
| `main.js` | Game state, update loop, input, HUD, wiring |
| `view.js` | Camera, terrain drop, projection and cached inverse ground rows |
| `render.js` | Background, ground, walls, puddles, pickups |
| `render-player.js` | The chosen figure: sprite frame, shadow, hop, dazed stars |
| `render-fx.js` | Plants, particles, speed lines, color grade, debris |
| `render-slip.js` | Ice sheen, skid marks, spray |
| `sprites.js` | Shared offscreen canvas helpers, pickup symbols, grade |
| `environment-sprites.js` | Cached painted woodland clusters, silhouette fog copies, seasonal stone/wire faces and ground light |
| `atmosphere.js` | Shared depth mist and arrival/fade curves (pure, unit tested) |
| `figure.js` | Figures: which frame when (intro, roll, dazed), loading and drawing sheets. Unit tested |
| `figure-select.js` | Figure cards on the start screen, stored choice |
| `figure-sheets.js` | Generated by `tools/build-sprites.py`: frame sizes and anchors per clip |
| `surfaces.js` | Painted earth plus procedural grass/gravel, seasonal shade/snow and cached mip levels |
| `surface-art.js` | Loads the two shared earth/stone material WebPs, with procedural fallbacks |
| `scenery.js` | Where roadside plants stand, derived from distance (no state) |
| `seasons.js` | Loads current horizon/forest first, others in idle time; blends horizon fog once |
| `environment-preview.js` | Deterministic environment fixture at `?preview=<season>#debug`, excluded from normal play |
| `fx.js` | Short-lived effects: stones, dust, sparkles |
| `ideas.js`, `leaderboard.js`, `name.js` | Bottom sheets for ideas and leaderboard, shared name storage and network errors |

**Game rules in short.** Difficulty follows the walls passed, not the time (ADR 0024): speed eases from 16 toward 28 units/s, the time between walls from 1.2 toward 0.65 s, the gap from 3.2 toward 1.95; the first five walls of each season are a breather, and after the first year (80 walls) gaps and intervals keep tightening slowly. Autumn gusts are announced 0.7 s ahead. Seasons change every 20 walls (spring: puddles, summer: faster and two gaps, autumn: wind gusts, winter: ice). Path surfaces change every 120–220 units (dirt normal, gravel bumpy, grass slower). Power-ups: helmet (extra life, stacks to 3), slow-mo (5 s), wider gaps (7 s).

**Testing hook.** `index.html#debug` exposes `window.rollDown` (`game()`, `start`, `intro`, `step`, `setSeason`, `spawn`, `update`); `step(dt)` advances one frame by hand (the wind strength follows `game().passed`, so set it too when you jump to autumn with `setSeason(2)`), for panes where `requestAnimationFrame` is paused during scripted browser tests. `?preview=autumn#debug` provides a frozen seasonal view; add `&surface=gravel` or `&surface=grass` to check surfaces. `&width=390&height=844` fixes the debug game frame for repeatable captures; `&near=4.8` shows a close approaching basket. Basket height is 1.65, with texture cropping to preserve wire proportions.

**Security on the page.** A CSP meta tag allows only own files and the worker URL. User text (names, ideas, leaderboard entries) is only ever set with `textContent`.

## The worker (`worker/`)

| File | Job |
|---|---|
| `src/index.js` | Routing, CORS, origin allowlist, size/type checks, rate limits, daily idea cap |
| `src/idea.js` | Validate an idea, build the GitHub issue (text in a code block, names stripped of markdown) |
| `src/score.js` | Validate a score, merge it into the top 20, per-IP limiter |
| `wrangler.toml` | Worker name, repo var, KV binding |

Limits: ideas 5 per hour per IP and 100 per day in total; scores 20 per hour per IP; bodies up to 4 KB; JSON only. Only `https://svengoerdes.github.io` may call it (extra dev origins via the `DEV_ORIGINS` env var, unset in production).

The GitHub token is a Cloudflare secret, never in the repo or the browser. Details in [operations.md](operations.md).
